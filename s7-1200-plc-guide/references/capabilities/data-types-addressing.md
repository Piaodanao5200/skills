# 数据类型与寻址规则

## R — 原文 (Reading)

> "对输入 (I) 或输出 (Q) 存储区（例如 I0.3 或 Q1.7）的引用会访问过程映像。" "要立即访问物理输入或输出，请在引用后面添加':P'（例如，I0.3:P、Q1.7:P）。" "可优化访问的数据块无固定的定义结构。数据元素在声明中仅包含一个符号名，在块中没有固定地址。"
>
> — Siemens AG，《S7-1200 可编程控制器系统手册》V4.2，ch5.2.1 p127–132；ch7.3.4 p208

## I — 方法论骨架 (Interpretation)

这一能力回答两个高频问题："这个变量该用什么数据类型/多大范围"和"这个地址怎么写才会生效"。寻址的核心是区分过程映像与立即外设访问：普通 I/Q 访问的是周期开始/末刷新的一份内存快照，最多一个扫描周期延迟；要立即读物理点必须加 `:P`（`I_:P` 只读且不更新映像，`Q_:P` 只写但会同时更新映像）。在 SCL 中写绝对地址必须加 `%` 前缀（如 `%M3.4`），否则编译报未定义变量。各存储区属性不同：I 过程映像不可强制，只能强制 `I_:P` 外设；L 局部存储器仅块内有效、不跨块传递。I/O 地址按 8 点数字量占 1 字节、模拟量每点 2 字节分组分配，即使模块只用 5 点也占满 1 字节。数据类型上：整数选型要按数值范围（Int −32768~32767、DInt 更大），存 −40000 必须用 DInt；浮点 Real 只有 6 位有效数字、LReal 15 位，相差 10^6（Real）时小数被"吃掉"（1e8+1 仍等于 1e8）。DB 分全局 DB 与背景 DB；默认"优化访问"DB 无固定地址、只能符号寻址，需要绝对/直接寻址的场合（Modbus DATA_PTR、Variant 的 STRUCT 实参、HSC 起始值）必须显式改为标准访问。时钟存储器位（0.5–10Hz 方波）与系统存储器位（FirstScan 等）本质是分配了特殊含义的普通 M 区，可被程序/通信改写破坏。

## A1 — 应用示例 (Application Example)

### 示例 1: 浮点精度（worked_example）
- **类型与来源**: 原书演算示例 c04，ch5.4.3 p138。
- **问题/输入**: Real 计算 `100 000 000 + 1`。
- **方法论的使用**: 两数相差 10^8 > 10^6（Real 有效 6 位），小数被大数吞掉。
- **结论**: 结果仍为 100 000 000，+1 丢失；需高精度改用 LReal（15 位）。
- **结果**: 手册给出演算结果 100 000 000 + 1 = 100 000 000。

### 示例 2: 模拟量标定公式（worked_example）
- **类型与来源**: 原书例题 c01，ch5.3 p133–134。
- **问题/输入**: 0–20mA 输入，模块返回 0–24768，测 50–100°C。
- **方法论的使用**: 工程单位值 = 50 + 输入值×(100−50)/(24768−0)；或用 NORM_X 标准化到 0.0–1.0 再 SCALE_X 标定。
- **结论**: 0→50°C、12384→75°C、24768→100°C（手册映射表）。
- **结果**: 手册给出完整映射表，验证公式。

### 示例 3: 立即读物理输入（合成演练）
- **类型与来源**: 合成演练，依据 p13/p20 规则。
- **问题/输入**: 启动 OB 中要判断 I0.0 当前电平。
- **方法论的使用**: 启动 OB 中读 I0.0 过程映像恒为 0，须写 `I0.0:P`。
- **结论**: 用 `I0.0:P` 得到物理电平。
- **结果**: 与手册规则一致。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个能力?
1. 写 SCL 时绝对地址编译报"未定义变量"，不知道要加 `%`。
2. 程序读到输入是旧值/0，怀疑过程映像与立即访问没分清。
3. 变量数值溢出，或浮点计算精度不对。
4. 要给 DB 加绝对寻址/给 Modbus 配 DATA_PTR，发现优化 DB 没有地址。
5. 分配 I/O 地址、规划模块占几个字节。

### 语言信号 (用户的话里出现这些就应激活)
- "I0.3:P 是什么意思 / 立即读输入" / "immediate input / peripheral access / :P"
- "SCL 绝对地址报错 / 加百分号" / "absolute address % / SCL syntax"
- "Real 精度不够 / 数值溢出" / "floating point precision / integer range / DInt"
- "优化 DB 没有地址 / 标准访问" / "optimized DB / standard access / symbolic addressing"
- "地址怎么分配 / 占几个字节" / "address allocation / byte alignment"

### 与相邻能力的区分（阶段 3 定稿）
- 与 `program-structure-decision` 的区别：那边定"逻辑放哪个块、状态存哪"，本能力定"变量类型与地址写法"；本能力是结构决策的基础（program-structure-decision depends-on 本能力）。
- 与 `data-consistency` 的区别：那边解决"多值读写撕裂"，本能力解决"单个变量类型/地址正确"；优化 DB 不匹配导致的数据丢失归 data-consistency。
- 与 `technology-motion-config` 的区别：那边用 NORM_X/SCALE_X 做工程标定，本能力提供这两条指令的公式与数据类型规则。

## E — 可执行步骤 (Execution)

**必需输入**: 变量用途（运算/计时/定位）；数值范围；是否需要立即访问/绝对寻址；DB 用途（是否需被 Modbus/HSC 按地址访问）。
**交付物与完成标准**: 一张"变量→类型→地址/访问方式"映射表，含边界核对（范围、精度、优化/标准访问）结论。

1. **定类型与范围** — 完成标准：整数按范围选 Int/DInt；浮点按精度选 Real/LReal；列出越界风险点。
2. **定地址/访问方式** — 完成标准：SCL 绝对地址加 `%`；需立即读写的用 `:P`（I 只读、Q 只写且更新映像）；I/O 按 8 点/2 点分组分配。
3. **定 DB 访问方式** — 完成标准：需绝对寻址/经典兼容的 DB 取消"优化访问"改标准访问；判停条件：若 Modbus DATA_PTR 指向优化 DB → 报错，先改标准访问。
4. **核对特殊存储位** — 完成标准：系统/时钟存储器位未被程序或通信改写；FirstScan/DiagStatusUpdate 使用正确。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此能力
- 要组织代码块、决定 FB/FC——用 `program-structure-decision`。
- 要解决多变量在中断下"值撕裂"——用 `data-consistency`。
- 要查某条指令完整参数表——走指令速查/手册检索。

### 作者在书中警告的失败模式
- **ce30**：改写系统/时钟存储器位破坏 FirstScan 等功能，依赖它的逻辑不察觉异常。
- 手册提示"示例 24768"疑为笔误，标定公式须以模块实际额定范围（0~27648 或 −27648~27648）为准。

### 作者的盲点 / 时代局限
- 手册锁定 V4.2（2016）；新型号数据类型/地址规则须查新版。
- 优化访问默认开启是 V4 行为，迁移老项目时注意绝对寻址失效。

### 容易混淆的邻近能力
- `program-structure-decision`、`data-consistency`、`technology-motion-config`。

## 相关能力（阶段 3 填充）

- used-by: `program-structure-decision`
- composes-with: `data-consistency`, `technology-motion-config`
