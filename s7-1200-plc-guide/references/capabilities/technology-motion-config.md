# 高速计数 / PID / 运动控制工艺组态

## R — 原文 (Reading)

> "'计数器操作'中所述的基本计数器指令限于发生在低于 S7-1200 CPU 扫描周期速率的计数事件。高速计数器 (HSC) 功能提供了发生在高于 PLC 扫描周期速率的计数脉冲。" "以恒定的采样时间间隔执行 PID 指令（最好在循环 OB 中）。由于 PID 回路需要一段时间来响应控制值的变化，因此请勿在每个循环中都计算输出值。请勿在主程序循环 OB（如 OB 1）中执行 PID 指令。"
>
> — Siemens AG，《S7-1200 可编程控制器系统手册》V4.2，ch10.1 p631；ch10.2 p666

## I — 方法论骨架 (Interpretation)

工艺组态的第一判断是"事件频率是否超过扫描速率"，这决定用普通指令还是专用硬件功能。高速计数（HSC）：普通计数器受扫描周期限制会漏计高频脉冲，HSC 由硬件实现，组态后无需调用指令即可运行，计数值在每个扫描周期的过程映像自动捕获。HSC 有四类功能（同步/门/捕获/比较）；门控由"软件门×硬件门"状态表决定内部门是否开；编码器监控按"启动装载首参考值→达参考值中断装新值与下一输出态→同步中断复位回首态"的低中断频率循环，实现高速精确定位。PID：以恒定采样间隔执行，必须放在循环中断 OB 而非 OB1（OB1 周期抖动会被误当作过程响应，破坏 P/I/D 计算）；调试走"测量→预调节/精确调节→上传 PID 参数→验证无错误"。模拟量标定：先用 NORM_X 把输入标准化到 0.0–1.0，再用 SCALE_X 标定到工程单位（注意电压型模块 NORM_X 的 MIN 应为 −27648）。运动控制：以工艺对象（TO，轴/PID 等带专用组态/调试/诊断 UI 的封装）为入口；开环轴用 PTO 脉冲+方向（占用板载/SB 高速输出，数量受 CPU 限制），闭环用模拟量或 PROFIdrive；编码器"绝对值可当增量用，增量不能当绝对值用"；TO 启动时做一致性检查（报文/电机类型/最大速度），不一致则报错或内部下调。错误排查走"ErrorID→原因→补救（如提供驱动器就绪信号）→MC_Reset 确认→重启命令"。

## A1 — 应用示例 (Application Example)

### 示例 1: 模拟量标定 NORM_X/SCALE_X（worked_example）
- **类型与来源**: 原书例题 c13/c01，ch8.7 p325–326、ch5.3 p133–134。
- **问题/输入**: 电流输入 0–27648 代表 −30.0–70.0°C。
- **方法论的使用**: NORM_X 标准化到 0.0–1.0 → SCALE_X 标定到 −30.0–70.0°C。
- **结论**: 两步换算出工程单位；电压型模块 MIN 取 −27648。
- **结果**: 手册给出程序段与换算逻辑；实际运行结果未说明。

### 示例 2: PID 放在循环中断 OB（worked_example，依据 f48/ce34）
- **类型与来源**: 合成演练，手册 ch10.2 p666/728。
- **问题/输入**: 整定一个温度 PID，原先挂在 OB1。
- **方法论的使用**: 把 PID 块移入循环中断 OB 获恒定采样；调试编辑器设采样时间→测量→预调节/精确调节→上传参数→检查状态无错误。
- **结论**: 采样时间恒定，调节品质可预期；放 OB1 会出现采样抖动导致振荡。
- **结果**: 与手册"请勿在 OB1 中执行 PID"一致。

### 示例 3: 编码器位置切换输出（worked_example，依据 f47）
- **类型与来源**: 合成演练，手册 ch10.1.2.5 p648。
- **问题/输入**: 按编码器位置切换输出状态。
- **方法论的使用**: 启动装载首参考值→达参考值中断装新值与下一输出态→同步中断复位回首态。
- **结论**: 以低中断频率实现高速精确定位。
- **结果**: 与手册状态控制循环范式一致。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个能力?
1. 编码器/高速脉冲计数不准、漏计，怀疑普通计数器不够快。
2. 要按位置/参考值触发输出，用 HSC 的门/比较/同步功能。
3. PID 控制振荡、品质差，采样时间忽长忽短。
4. 4–20mA/0–10V 信号要换算成温度/压力等工程单位。
5. 要配开环/闭环轴（PTO 脉冲或 PROFIdrive），轴数受什么限制。
6. 运动控制启动报一致性错误/ErrorID，轴无法启用。

### 语言信号 (用户的话里出现这些就应激活)
- "高速计数 / 编码器漏计" / "high speed counter / HSC / encoder missed pulses"
- "PID 整定 / 振荡 / 采样时间" / "PID tuning / sampling time / oscillation"
- "标定 / 工程单位 / 4-20mA" / "scaling / engineering units / NORM_X SCALE_X"
- "运动控制 / 轴 / PTO / 伺服" / "motion control / axis / PTO / servo"
- "TO 一致性错误 / ErrorID" / "technology object consistency / ErrorID"
- "绝对值 / 增量编码器" / "absolute / incremental encoder"

### 与相邻能力的区分（阶段 3 定稿）
- 与 `realtime-scan-interrupt` 的区别：那边管中断/扫描机制本身，本能力把循环中断用于 PID、用 HSC 突破扫描速率限制（composes-with）。
- 与 `data-types-addressing` 的区别：那边提供 NORM_X/SCALE_X 的公式与类型规则，本能力用于工程标定场景（composes-with）。
- 与 `power-budget-sizing` 的区别：那边算供电，本能力的 PTO 轴数受 CPU 板载输出资源限制，选型时相关。
- 与 `device-replacement` 的区别：V3→V4 换型时运动控制 TO 版本升级/字段重命名归 device-replacement。

## E — 可执行步骤 (Execution)

**必需输入**: 事件/脉冲频率与扫描速率对比；控制目标（计数/定位/温控/运动）；编码器类型；开环还是闭环；模拟量信号范围；CPU 型号（PTO 能力）。
**交付物与完成标准**: 工艺组态方案——选型（HSC/PID/TO/标定）+ 组态步骤 + 调试/排障路径，含条件分支与失败处理。

1. **选工艺功能** — 完成标准：脉冲频率>扫描速率→HSC；恒采样控制→PID+循环中断 OB；轴→TO（开环 PTO/闭环）；模拟量→NORM_X+SCALE_X。
2. **组态 HSC（如适用）** — 完成标准：按门控状态表配软件/硬件门；编码器用同步+比较功能；监控按低中断频率循环；判停条件：只建 OB 未使能事件 → 中断不触发，回到使能。
3. **组态 PID（如适用）** — 完成标准：PID 块置于循环中断 OB（非 OB1）；采样时间恒定；调试走测量→预调节/精确调节→上传→验证；判停条件：挂在 OB1 → 先迁移。
4. **组态运动（如适用）** — 完成标准：TO 轴类型与驱动器报文/电机/最大速度一致（一致性检查通过）；编码器类型匹配；记录可支持的轴数。
5. **排障** — 完成标准：按 ErrorID→原因→补救→MC_Reset 确认→重启命令闭环；运动错误定位到具体动作。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此能力
- 要组态通用通信连接——用 `communication-config`。
- 要理解中断/扫描机制——用 `realtime-scan-interrupt`。
- 要逐条查某工艺指令的参数表——走手册检索。

### 作者在书中警告的失败模式
- **ce34**：把 PID 放 OB1 每周期都算——采样时间随负载抖动，参数失效/振荡。
- **ce35**：把增量编码器当绝对值用——断电丢位置、实际值错误、轴无法启用。
- **ce36**：TO 与驱动器/传感器组态不一致——启动时报错或速度被内部下调。
- **f39/f40**：只建中断 OB 未使能硬件事件导致不触发；循环中断相移未错开互相抢占。

### 作者的盲点 / 时代局限
- 手册锁定 V4.2（2016）；运动控制 V1/V2 库在新版由 V3/V5 指令替换，旧库不支持（详见 device-replacement）。
- 假设读者有 TIA Portal 工艺对象环境与驱动器；厂商视角只讲西门子 TO/驱动方案。
- 功能安全相关运动（安全扭矩关闭等）着墨极少。

### 容易混淆的邻近能力
- `realtime-scan-interrupt`、`data-types-addressing`、`power-budget-sizing`、`device-replacement`。

## 相关能力（阶段 3 填充）

- composes-with: `realtime-scan-interrupt`, `data-types-addressing`
- 对照: `power-budget-sizing`（PTO 轴数受板载资源限制）、`device-replacement`（TO 版本升级）
