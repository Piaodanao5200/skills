# 程序下载、调试与在线同步

## R — 原文 (Reading)

> "警告：在 RUN 模式下下载的风险。在 RUN 模式下向 CPU 中下载更改时，这些更改将立即影响过程操作。在 RUN 模式下更改程序可能会引起意外的系统操作，进而导致人员死亡、重伤和/或设备损坏。"
>
> — Siemens AG，《S7-1200 可编程控制器系统手册》V4.2，ch15.14 p1510；ch7.7 p233–235；ch7.8 p236–237

## I — 方法论骨架 (Interpretation)

这一能力覆盖"把程序弄进 CPU、在线调试、保持项目与 CPU 一致"的全套操作，核心是"下载前先判兼容，改动前先想安全，值冲突先比较再决定"。下载前第一关是兼容性：组态的 CPU 与实际 CPU 容量/I/O 必须匹配（组态 1215C 却接 1212C → 工作存储器不足 → 禁止下载，须改设备）；下载失败按"修正→重试→清空装载存储器/复位出厂→重下"升级路径处理，别盲目重试。在线/离线不一致时有四个同步选项，原则是"先在线/离线比较看差异，再决定上传还是覆盖下载"，防止现场被 WRIT_DBL 改过的值被盲目覆盖。上传程序块是"程序块文件夹→转到在线→上传→确认选项"。调试工具要分清三种能力：监视只读不改程序顺序；修改仅临时改值（下一周期被程序覆盖）；强制把值锁存在 CPU 中、不受程序刷新覆盖，且只能强制 `:P` 外设——误用会导致输出长期锁在危险状态。监视表的触发器要选对（要观察写入输出的值选"扫描周期结束、写物理输出前"）。RUN 模式下载是高风险操作：改动立即生效、STEP 7 默认在有更改时优先尝试 RUN 下载；删除的输出逻辑会保持最后状态直到下次上电/STOP，HSC/PTO 继续运行；含数据日志/READ_DBL 的块会报临时错误 80C0/82C0（须稍后重试、不能在同一 OB 内）。要在 RUN 下给 DB 加变量且不重新初始化，须启用"下载而不重新初始化"并在 100 字节预留区内加；超过 20 个块必须 STOP。DB 在线值快照可捕获并复制到起始值。STOP 下启用输出前必须确认不会导致意外动作（停止≠安全）。

## A1 — 应用示例 (Application Example)

### 示例 1: 下载到不同容量 CPU（worked_example，依据 f32）
- **类型与来源**: 合成演练，手册 ch7.7 p233–235。
- **问题/输入**: 项目组态 1215C，实际接的是 1212C。
- **方法论的使用**: 两判据——工作存储器容量、I/O 点；1212C 工作存储器不足 → 禁止下载 → 更改设备为 1212C 后重编。
- **结论**: 下载前拦截不兼容，避免失败重试。
- **结果**: 与手册判据一致。

### 示例 2: 在线/离线同步决策（worked_example，依据 f34）
- **类型与来源**: 合成演练，手册 ch7.8 p236–237。
- **问题/输入**: 在线 CPU 的 DB 起始值被 WRIT_DBL 改过，比项目新。
- **方法论的使用**: 弹同步框 → 先在线/离线比较看差异 → 决定"同步上传"（保留现场值）还是"覆盖下载"（用项目值）。
- **结论**: 先比较再定，防止现场值被覆盖或漏同步。
- **结果**: 与手册四选项决策一致。

### 示例 3: RUN 下载临时错误（worked_example，依据 f64/ce27）
- **类型与来源**: 合成演练，手册 ch15.14.7 p1521。
- **问题/输入**: RUN 下载激活期间 WRIT_DBL 报 82C0。
- **方法论的使用**: 判为临时错误（非永久故障）→ 稍后重试、不在同一 OB 内重试。
- **结论**: 避免把临时错误误判为永久故障。
- **结果**: 与手册"稍后重试"规则一致。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个能力?
1. 要把程序下载到 CPU，或下载失败反复重试，想知道原因和恢复路径。
2. 在线 CPU 的值和项目里不一样，不知道该上传还是覆盖。
3. 要在线监视/临时改值/强制变量调试，分不清三者后果。
4. 想在 RUN 模式下改程序又担心影响正在运行的机器。
5. 要把现场 CPU 的程序传回项目，或做一个现场值的备份快照。
6. 调用结构显示红色时间戳冲突，下载前要排查。

### 语言信号 (用户的话里出现这些就应激活)
- "下载程序 / 下载失败" / "download program / download failed"
- "在线离线不一致 / 同步 / 上传" / "online offline mismatch / synchronize / upload"
- "监视 / 修改 / 强制变量" / "watch table / modify / force value"
- "RUN 模式下载 / 在线改程序" / "download in RUN / online change"
- "不重新初始化 / 快照" / "download without reinitialization / snapshot"
- "时间戳冲突" / "timestamp conflict / call structure"

### 与相邻能力的区分（阶段 3 定稿）
- 与 `online-troubleshooting` 的区别：那边是"定位故障"的取证判读，本能力是"改程序/下载/同步/强制"的调试操作；先诊断定位再决定是否下载修改（composes-with）。
- 与 `data-consistency` 的区别：那边解决数据读写撕裂，本能力用快照/起始值搬运现场值；WRIT_DBL 的临时错误归本能力。
- 与 `storage-firmware-maintenance` 的区别：那边是卡/固件/出厂复位类维护，本能力是程序与值的在线操作（composes-with）。
- 与 `program-structure-decision` 的区别：那边设计结构，本能力把结构编译后的块下载并调试。

## E — 可执行步骤 (Execution)

**必需输入**: 项目组态的 CPU 型号与实际型号；下载目标模式（STOP/RUN）；在线/离线是否一致；是否涉及强制/分布式 I/O；要改的块数量。缺实际 CPU 型号时先确认。
**交付物与完成标准**: 下载/调试执行单——兼容性判定 + 下载/上传/同步路径 + 调试手段选择 + 安全确认，含失败处理。

1. **下载前兼容判定** — 完成标准：核对容量/I/O 两判据；不兼容 → 更改设备重编；判停条件：组态 1215C 接 1212C 等工作存储器不足 → 禁止下载。
2. **处理在线/离线差异** — 完成标准：先在线/离线比较看差异，再选四选项之一（上传/覆盖/同步）；被 WRIT_DBL 改过的值不盲目覆盖。
3. **选择调试手段** — 完成标准：只读用监视、临时改值用修改、需锁存用强制（仅 `:P` 外设）；触发器按观察目标选对；STOP 下启用输出前确认安全（ce72/ce42）。
4. **执行下载（含 RUN 模式判定）** — 完成标准：默认优先 STOP 下载；若 RUN 下载，确认安全后果、≤20 块、预留区机制；删除逻辑/HSC/PTO 的残留行为已告知。
5. **失败与验证** — 完成标准：下载失败按升级路径处理（修正→重试→清空存储器→复位）；临时错误 80C0/82C0 稍后重试；下载后验证块一致、强制已清除、时间戳无冲突。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此能力
- 要定位故障根因——用 `online-troubleshooting`。
- 要更新固件/格式化卡/恢复出厂——用 `storage-firmware-maintenance`。
- 要做 V3→V4 换型——用 `device-replacement`。

### 作者在书中警告的失败模式
- **ce25**：误把 RUN 下载当无风险小改——改动立即影响过程，可致伤亡/损坏。
- **ce26**：RUN 下载删除逻辑后以为立即失效——输出保持最后状态、HSC/PTO 继续运行到下次上电/STOP。
- **ce27/ce64**：把临时错误 80C0/82C0 当永久故障，或在同一 OB 内重试。
- **ce24**：忘记强制值随项目/存储卡传播；ce31：误以为下载会重置保持性数据。
- **f72/ce42**：STOP 下启用输出致意外动作；带分布式 I/O/强制时无法启用输出。

### 作者的盲点 / 时代局限
- 手册锁定 V4.2（2016）；"默认优先 RUN 下载"等 IDE 行为在新版 TIA Portal 可能变化。
- 假设读者有 TIA Portal 环境与在线硬件；STOP≠安全的判断需要工程经验补充。
- 功能安全相关的下载约束（如安全程序下载认证）缺席。

### 容易混淆的邻近能力
- `online-troubleshooting`、`data-consistency`、`storage-firmware-maintenance`、`program-structure-decision`。
