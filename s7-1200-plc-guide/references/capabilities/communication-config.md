# 通信协议选型与组态

## R — 原文 (Reading)

> "PROFINET 网络中的设备在分配名称后才可与 CPU 连接。" "要立即修改 IP 参数……必须在'以太网地址'页面的 CPU'属性'中选中'在设备上直接设置 IP 地址'单选按钮。" "可以将外部 24V DC 电源……" 警告：密码保护不适用于用户程序指令的执行，包括通信功能……PLC 到 PLC 通信……不受 CPU 中安全等级的限制。
>
> — Siemens AG，《S7-1200 可编程控制器系统手册》V4.2，ch11.2 p912–913/1041；ch13.2 p1223；ch7.6.1 p226

## I — 方法论骨架 (Interpretation)

通信配置的第一步是选协议、定角色，第二步才是组态连接——顺序反了会大量返工。PROFINET：IO 控制器/IO 设备是确定角色，还有"智能设备"（既做预处理又挂到上位控制器的 CPU）与"共享设备"（多个控制器各独占分配一台 IO 设备的不同子模块）；设备必须先"分配名称"才能连接，名称不匹配则数据交换不运行（f56）。连接建立的路径是"网络视图拖端口→属性配参数→设备和网络编辑器配 GET/PUT→双方插通信指令绑 DB"，前提是通信伙伴已创建。PROFINET 设备名不匹配是数据交换不运行的典型前置故障，排障走"在线和诊断→指定设备名称→更新列表→分配名称→两处一致后启动"。运行时改 IP 用 T_CONFIG，但前置条件是 CPU 属性里勾选"在设备上直接设置 IP 地址"。Modbus：先定主从角色（CPU 读远程仪表→主站/客户端，用功能码 03 读保持寄存器），再根据介质组态；多 TCP 连接必须每个连接一个独立背景 DB、连接 ID、IP 端口。RS485/PtP 物理层：只端接和偏置总线两端设备，中间设备 Off，否则多点端接导致信号反射。PUT/GET 通信默认禁用，须设保护级别非"无访问"+勾选允许 PUT/GET+下载才生效。关键安全盲区：密码保护只保护编程设备/HMI 访问路径，不保护通信指令执行，PLC 到 PLC 通信不受安全等级限制——"有密码"不等于"数据不被读写"。PtP 的 DONE/NDR/ERROR 只置位一个周期，须锁存；Port_Config 改的端口参数不永久保存，STOP→RUN 后恢复组态值。

## A1 — 应用示例 (Application Example)

### 示例 1: PROFINET 设备名分配排障（worked_example，依据 f56）
- **类型与来源**: 合成演练——手册 ch15.3 p1488–1489 给出三步操作，未给完整项目。
- **问题/输入**: CPU 与 PROFINET 从站数据交换不运行，怀疑设备名不匹配。
- **方法论的使用**: 在线和诊断 → 指定设备名称 → 更新列表 → 分配名称 → 确认"组态名"与"在线名"两处一致后启动。
- **结论**: 名称一致后数据交换启动。
- **结果**: 与手册"两处名称一致"的验证条件一致。

### 示例 2: Modbus 主站读仪表（worked_example，依据 f51/c20）
- **类型与来源**: 合成演练 + 原书例题 c20（ch13.5.3.5 p1373–1374）。
- **问题/输入**: CPU 要通过 RS485 读远程仪表的 100 个保持寄存器。
- **方法论的使用**: 设为主站/客户端；首扫描用 Comm_Load 组态端口；用 Modbus_Master 从从站#2 地址 400001 读 100 字到 MW500–MW698；锁存 DONE/ERROR。
- **结论**: 角色→功能码→端口组态→程序调用顺序清晰。
- **结果**: 手册给出四段程序结构；实际读取结果未说明。

### 示例 3: RS485 端接（worked_example，依据 p40）
- **类型与来源**: 合成演练，手册 ch13.2 p1223–1224。
- **问题/输入**: RS485 总线上 5 台设备。
- **方法论的使用**: 仅两端设备开关置 On（端接+偏置），中间 3 台置 Off。
- **结论**: 避免多点端接导致信号反射。
- **结果**: 与手册一致。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个能力?
1. 要给 CPU 配 PROFINET/PROFIBUS/PtP/Modbus，不知道选哪个、定什么角色。
2. 通信建不起来，PROFINET 从站"数据交换不运行"。
3. 要在运行时改 IP/设备名，问用什么指令、什么前置条件。
4. 多个 Modbus TCP 连接不知道怎么分配端口/ID/背景 DB。
5. RS485 总线上多台设备，问终端电阻怎么拨。
6. 以为设了 CPU 密码就能防住远程 PUT/GET 读写数据。

### 语言信号 (用户的话里出现这些就应激活)
- "PROFINET / Modbus 怎么组态" / "configure PROFINET / Modbus"
- "设备名不匹配 / 数据交换不运行" / "device name mismatch / no data exchange"
- "主站从站怎么选 / 功能码" / "master slave role / function code / holding register"
- "RS485 终端电阻 / 端接" / "RS485 termination / bias"
- "PUT/GET 默认禁用 / 允许通信" / "PUT GET access / permit PUT GET"
- "运行时改 IP" / "T_CONFIG / set IP at runtime"

### 与相邻能力的区分（阶段 3 定稿）
- 与 `data-consistency` 的区别：那边管通信缓冲区/一致性数据的读写时序，本能力管连接的建立与组态（composes-with）。
- 与 `power-wiring-installation` 的区别：那边管 RS485 物理接线/接地，本能力管协议/角色/端口组态。
- 与 `online-troubleshooting` 的区别：那边是从 LED/诊断缓冲区入手的通用排障链，本能力专注"通信建不起来/设备名/PUT-GET"这类组态前置问题。
- 与 `device-replacement` 的区别：更换 CPU 后 GET/PUT 默认启用等兼容性变化归 device-replacement。

## E — 可执行步骤 (Execution)

**必需输入**: 协议类型（PN/PB/PtP/Modbus）；网络角色（主/从/控制器/设备）；通信伙伴是否已创建；介质（RJ45/RS485）；是否需要多连接；PUT/GET 与安全需求。
**交付物与完成标准**: 组态方案——协议/角色选择表 + 连接组态步骤 + 前置条件核对（设备名/伙伴已建/PUT-GET 启用/端接），含失败处理。

1. **选协议与角色** — 完成标准：按"读远程数据→Modbus 主站""周期确定性 IO→PROFINET 控制器"等规则定协议与角色，再选功能码/数据区。
2. **核对前置条件** — 完成标准：通信伙伴已创建；PROFINET 设备名已分配且两处一致；PUT/GET 已按需要启用；判停条件：设备名不匹配 → 先走 f56 分配名称，不继续。
3. **组态连接** — 完成标准：PROFINET 走网络视图拖端口→属性配参数→GET/PUT 配 DB→双方插指令；Modbus TCP 每连接独立背景 DB/ID/端口；RS485 仅两端端接。
4. **写通信程序** — 完成标准：首扫描初始化端口、调用主/从指令、DONE/NDR/ERROR 锁存、错误码处理；PtP 状态当拍锁存。
5. **验证连通** — 完成标准：在线视图确认连接建立、数据交换运行；运行时改 IP 须先勾"在设备上直接设置 IP 地址"；确认未把密码保护当数据防护（ce20）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此能力
- 要处理通信数据的一致性读写时序——用 `data-consistency`。
- 要查某条指令的完整参数表——走手册检索/DIGEST。
- 是 PROFIBUS 步-by-step 组态专流程（本手册轻缺口）——用路由入口查 RS485 端接等规则并回手册。

### 作者在书中警告的失败模式
- **ce20**：以为设了 CPU 密码就保护通信——PLC 到 PLC 通信不受安全等级限制。
- **ce21**：未授权访问/把 PLC 变量改成无效值——弱口令、HTTP、放宽 Everybody 权限。
- **ce40**：PtP 的 DONE/NDR/ERROR 只置位一周期，未在当拍锁存导致错过事件。
- **ce41**：以为 Port_Config 改的端口参数永久保存，STOP→RUN 后"变回去"。
- **ce39**：把扩展指令 8x 错误码当无害提示（CPU 仍 RUN）导致带病运行。

### 作者的盲点 / 时代局限
- 手册锁定 V4.2（2016）；早期 PtP/USS/Modbus（ch13.6–13.9）是旧模块遗留，新项目不应照搬。
- PROFIBUS 组态专章在候选层是轻缺口，仅 RS485 物理层规则充分；厂商视角只讲西门子方案。
- 网络安全着墨极少——密码保护非数据防护，现代工业安全需求需另查资料。

### 容易混淆的邻近能力
- `data-consistency`、`power-wiring-installation`、`online-troubleshooting`、`device-replacement`。

## 相关能力（阶段 3 填充）

- composes-with: `data-consistency`, `power-wiring-installation`
- 对照: `online-troubleshooting`（通信建不起来类问题）、`device-replacement`（换型后 GET/PUT 变化）
