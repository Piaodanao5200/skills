# 存储卡、固件与出厂复位维护

## R — 原文 (Reading)

> "警告：插入存储卡之前，请检查并确认 CPU 当前未执行任何操作。如果将存储卡……插入到正在运行的 CPU，CPU 将立即进入 STOP 模式，这可能引起过程中断，进而导致人员死亡或严重受伤。" "注意：请勿使用 Windows 的格式化程序……重新格式化存储卡……CPU 将无法再使用该存储卡。" "警告：安装已上电的 S7-1200 或相关设备……"
>
> — Siemens AG，《S7-1200 可编程控制器系统手册》V4.2，ch5.5.1 p152；ch5.5.5 p162；ch15.5–15.7 p1491–1495

## I — 方法论骨架 (Interpretation)

这一能力管 CPU 的"带外"维护：存储卡、固件、出厂复位、备份恢复，核心是"先分清卡的用途、确认 CPU 空闲、守住操作步骤与不可逆边界"。存储卡三类用途：传送卡（给多台 CPU 灌同一程序，用完取出）、程序卡（作外部装载存储器长期驻留，取出即 STOP）、固件更新卡；决策按"是否禁用内部→外部复制 × 有无作业文件"两维判断插卡后 CPU 行为。制作传送卡走 7 步（插无写保护空白卡→选传送→拖入 CPU→装载；勿删 `__LOG__`/`crdinfo.bin` 隐藏文件）；使用传送卡时 CPU 在 RUN 插卡会自动切 STOP、LED 交替闪示复制中、完成后必须先取卡再设 RUN。固件更新两条途径：存储卡方式（解压 zip 到卡根生成 FWUPDATE.S7S→确认 CPU 空闲插卡→保持 24V 等 LED 完成→取卡重启）与 STEP 7 在线方式（在线和诊断→功能→固件更新→选兼容文件→运行更新→用新固件启动，不重启则旧固件仍激活）。写入类操作有硬前提：插卡前 CPU 必须空闲（运行中插卡强制 STOP，可致事故）、固件更新全程保持 24V、中途断电可能变砖、跨大版本须按升级路径（V3.0 不能一步到 V4.x）。复位为出厂设置保留了保留 IP 决策与 MAC 不变；格式化卡后必须"移卡重启或不移卡重启"二选一，不能直接切 RUN。恢复出厂/读卡前要理解三级存储（装载/工作/保持性）与暖启动 vs MRES 的区别——MRES 清工作/保持性区、重载装载存储器，但不清诊断缓冲区和永久 IP。备份/恢复按矩阵选方式（监视值快照可编辑、从在线设备备份仅 STOP 且不可编辑）；备份保持性数据须禁用写访问；来路不明的备份不得恢复。忘记密码用空传送卡擦除恢复（原程序不可恢复）。

## A1 — 应用示例 (Application Example)

### 示例 1: 用传送卡给多台 CPU 灌程序（worked_example，依据 f19/f20）
- **类型与来源**: 合成演练，手册 ch5.5.3 p156–158。
- **问题/输入**: 要给 10 台同型号 CPU 灌同一程序。
- **方法论的使用**: 制作传送卡（无写保护空白卡→选传送→拖入 CPU→装载，保留隐藏文件）；对每台 CPU 在其 STOP/空闲时插卡→LED 交替闪示复制→完成后取卡→设 RUN。
- **结论**: 一台卡重复灌 10 台；每台"复制完成后取卡再设 RUN"。
- **结果**: 与手册 7 步制作 + 4 步使用流程一致。

### 示例 2: 固件在线更新（worked_example，依据 f58）
- **类型与来源**: 合成演练，手册 ch15.6 p1493–1494。
- **问题/输入**: 用 STEP 7 在线刷固件。
- **方法论的使用**: 在线和诊断→功能→固件更新→选兼容文件→运行更新→用新固件启动模块。
- **结论**: 不执行"用新固件启动"则旧固件仍激活。
- **结果**: 与手册"更新后须复位启动"条件一致。

### 示例 3: 复位出厂保留 IP（worked_example，依据 f57）
- **类型与来源**: 合成演练，手册 ch15.5 p1491–1492。
- **问题/输入**: 清除保持性数据但保留 IP。
- **方法论的使用**: 在线→STOP→复位出厂→勾"保留 IP"→确认（MAC 固定不变）。
- **结论**: 保持性数据清除、IP 保留、MAC 不变。
- **结果**: 与手册"保留/删除 IP 决策"一致。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个能力?
1. 要给多台 CPU 批量灌程序，选传送卡还是程序卡。
2. 要更新 CPU 固件，选存储卡方式还是 STEP 7 在线方式，怕中途变砖。
3. 卡"读不出来"想格式化，或误删了隐藏文件导致卡失效。
4. 要恢复出厂/复位，纠结会不会丢 IP、丢保持性数据、清不清诊断缓冲区。
5. 要备份/恢复 CPU 程序与数据，不知道选哪种备份方式。
6. 忘记 CPU 密码，想恢复访问。

### 语言信号 (用户的话里出现这些就应激活)
- "传送卡 / 程序卡 / 固件卡" / "transfer card / program card / firmware card"
- "刷固件 / 固件更新" / "firmware update / firmware card"
- "格式化存储卡 / 卡读不出来" / "format memory card / card not recognized"
- "恢复出厂 / 复位 / MRES" / "reset to factory / MRES / retain IP"
- "备份 / 恢复 CPU" / "backup / restore CPU / snapshot"
- "忘记密码" / "forgot password / password recovery"

### 与相邻能力的区分（阶段 3 定稿）
- 与 `device-replacement` 的区别：那边是 V3→V4 换型/版本兼容流程，本能力是卡/固件/复位/备份的维护操作；更换时"V3 传送卡不兼容"归 device-replacement（composes-with）。
- 与 `program-download-debug` 的区别：那边是程序/值的在线下载调试，本能力是带外维护与卡固件操作（composes-with）。
- 与 `online-troubleshooting` 的区别：那边处理运行期诊断事件，本能力处理卡/固件类故障恢复（如无效卡恢复）。
- 与 `power-wiring-installation` 的区别：那边提供"插卡前断电、防静电"的安全前提，本能力执行具体维护步骤。

## E — 可执行步骤 (Execution)

**必需输入**: 维护类型（灌程序/刷固件/复位/备份/恢复/密码恢复）；CPU 当前状态（RUN/STOP/空闲）；卡类型与写保护状态；固件版本与升级路径；是否需保留 IP/保持性数据。缺 CPU 状态时先确认，不得假设空闲。
**交付物与完成标准**: 维护执行单——类型决策 + 逐步操作 + 前置安全确认 + 不可逆边界告知，含失败处理。

1. **决策与前置确认**
   - 完成标准：选对卡用途/固件途径/备份方式；确认 CPU 空闲（运行中插卡会强制 STOP，ce16）；确认 24V 稳定、跨版本按升级路径。
   - 判停条件：CPU 正在控制过程且未完成急停 → 停止插卡/更新，先做安全隔离。

2. **执行维护操作**
   - 完成标准：按对应流程逐步操作（传送卡 7 步、固件在线 6 步、复位 5 步、备份/恢复按先决条件）；保留隐藏文件、不用 Windows 格式化、不用写保护卡跑配方。

3. **处理恢复路径**
   - 完成标准：无效/不兼容卡按"取卡→STOP-RUN/MRES/循环上电→下载有效程序"恢复；忘记密码用空传送卡擦除（告知原程序不可恢复）。

4. **验证**
   - 完成标准：LED 正常、固件版本正确（已用新固件启动）、卡可正常使用、格式化后已二选一重启；备份/恢复内容一致；诊断缓冲区无新错误。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此能力
- 要做 V3→V4 设备更换——用 `device-replacement`。
- 要下载/调试程序——用 `program-download-debug`。
- 要查订货号/备件端子排表——走 reference-tables.md 检索。

### 作者在书中警告的失败模式
- **ce14/ce15**：用 Windows 格式化 SIMATIC 卡、删除 `__LOG__`/`crdinfo.bin` 隐藏文件 → 卡彻底失效。
- **ce16**：向运行中 CPU 插卡 → 立即 STOP、过程中断甚至伤亡。
- **ce17**：V3.0 传送卡插入 V4.x CPU → 不兼容报错。
- **ce18**：固件更新中途断电/未确保 CPU 空闲 → 变砖/意外停机。
- **ce19**：写保护卡导致配方/数据日志指令报错；ce06：徒手拿卡 ESD 损坏。

### 作者的盲点 / 时代局限
- 手册锁定 V4.2（2016）；固件升级路径、复位行为在新版固件可能变化。
- "原程序不可恢复""不可回退"等不可逆边界须向用户明确告知，不能静默执行。
- 功能安全/网络安全缺席：忘记密码的擦除恢复不涉及安全审计，现代工业场景需另查。

### 容易混淆的邻近能力
- `device-replacement`、`program-download-debug`、`online-troubleshooting`、`power-wiring-installation`。
