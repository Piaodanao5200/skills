# 功率预算核算与供电选型

## R — 原文 (Reading)

> "每个 CPU 都提供了 5 V DC 和 24 V DC 电源……如果扩展模块的 5 V DC 功率要求超出 CPU 的功率预算，则必须拆下一些扩展模块直到其功率要求在功率预算范围内……如果 24 V DC 的功率要求超出 CPU 的功率预算，则可以增加外部 24 V DC 电源……警告：将外部 24 V DC 电源与 DC 传感器电源并联会导致这两个电源之间有冲突……"
>
> — Siemens AG，《S7-1200 可编程控制器系统手册》V4.2，附录 B「计算功率预算」p1780；ch4.2 功率预算 p61

## I — 方法论骨架 (Interpretation)

S7-1200 的 CPU 自带两路相互独立、有硬上限的电源预算：5V 供 CPU 自身与扩展模块总线，24V 传感器电源供本地输入点与继电器线圈。核算的第一步是查清该 CPU 型号的两路预算值与最大模块数；第二步把每个 SM/CM/SB 的 5V 需求、每个 24V 输入点（按 4mA/点）与继电器线圈（按 11mA/点）逐项累加；第三步分别用预算减去总需求，得到两路差额。5V 差额为负时没有"外挂 5V"的选项，只能拆模块或换更大 CPU；24V 差额为负时可以加独立外部 24V 电源，但绝不允许并到 CPU 传感器电源上——两个电源会互相拉扯电压，导致寿命缩短、立即故障或系统运行不确定。外部电源与传感器电源只能分别给不同位置供电，并把所有非隔离 M 端子接到同一参考电位。内部继电器线圈功率已计入 CPU 预算，不要重复计算。这套方法把"这个 CPU 带不带得动"从凭经验估算，变成给定组态即可独立复算的定量判定。

## A1 — 应用示例 (Application Example)

### 示例 1: 附录 B 表 B-1 功率预算算例
- **类型与来源**: 原书例题（worked_example），附录 B「计算功率预算」p1781–1782，表 B-1。
- **问题/输入**: CPU 1214C AC/DC/继电器（5V 预算 1600mA、24V 预算 400mA）+ 1×SB1223 + 1×CM1241 + 3×SM1223 + 1×SM1221，共 48 输入、36 输出。
- **方法论的使用**:
  - 5V 需求 = 50(SB1223) + 220(CM1241) + 3×145(SM1223) + 105(SM1221) = **810 mA**
  - 24V 需求 = 56(CPU 14 入) + 8(SB 2 入) + 3×8×4(SM1223 24 入) + 3×8×11(24 继电器线圈) + 8×4(SM1221 8 入) = **456 mA**
- **结论**: 5V 差额 = 1600 − 810 = **790 mA（充足）**；24V 差额 = 400 − 456 = **−56 mA（缺 56 mA）**，须加至少 56 mA 的独立外部 24V 电源，且不得与传感器电源并联。
- **结果**: 手册表 B-1 给出的差额即"5V=790mA、24V=(56)mA"；本次补缺口时独立复算逐项一致（见 appendix-source.md 复算校验段）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个能力?
1. 手上有一份 CPU + SM/CM/SB 清单，想知道供电够不够、要不要再加电源。
2. 现场模块装上后不识别，或 CPU 报供电相关错误，怀疑功率预算超限。
3. 24V 传感器电源带不动全部输入点，打算"再并一个 24V 电源"（典型的危险直觉，必须纠正）。
4. 选型阶段在 1211C/1212C/1214C/1215C/1217C 之间比较谁能带下这套模块。

### 语言信号 (用户的话里出现这些就应激活)
- "这个 CPU 带得动这几个模块吗" / "can this CPU power these modules"
- "算一下功率预算" / "calculate the power budget" / "power supply sizing"
- "24V 不够用能并联一个电源吗" / "can I parallel another 24V supply"
- "5V/24V 余量还有多少" / "current headroom / remaining current"

### 与相邻能力的区分（阶段 3 定稿）
- 与 `installation-wiring-safety` 的区别：本能力算"电够不够"，那边管"怎么装、怎么接地、怎么做浪涌抑制"；先算预算，再交安装规范施工（composes-with）。
- 与 `system-design-workflow` 的区别：那是零起点的七步系统设计流程，本能力只承担其中"功率预算"这一步的定量核算。
- 与 `device-replacement` 的区别：更换 CPU 型号后才需要重算预算，是先后衔接而非同一任务（composes-with）。

## E — 可执行步骤 (Execution)

**必需输入**: CPU 型号；扩展模块清单（SM/CM/SB 型号与数量）；24V 负载点数（数字量输入 4 mA/点、继电器线圈 11 mA/点）。缺失 CPU 型号或模块清单时必须先询问，不得用算例值猜测。
**交付物与完成标准**: 一张两行表（5V、24V 各列预算/总需求/差额，单位 mA，差额取整数、容差 0）；24V 差额<0 时给出外部电源最小容量，并附"独立供电、不得并联、M 共点"硬约束。

1. **查 CPU 预算与模块上限**
   - 完成标准：从「各 CPU 供电预算速查」记录该型号 5V/24V 预算值与最大 SM 数。
   - 判停条件：模块数超过上限 → 提示换 CPU 或减少模块，回到选型，不再继续累加。

2. **累加 5V 需求**
   - 完成标准：逐模块取 5V 需求求和得 Σ5V；未在速查表中的型号必须回附录 A 逐查，不得套用算例值。

3. **累加 24V 需求**
   - 完成标准：本地输入 4mA/点 + 各模块输入 4mA/点 + 继电器线圈 11mA/点求和得 Σ24V；内部继电器线圈不重复计入。

4. **算差额并判定**
   - 完成标准：5V/24V 预算各减总需求；5V<0 → 必须拆模块/换 CPU；24V<0 → 输出外部电源最小容量（mA）；均≥0 → 判定充足。

5. **复核两条硬约束**
   - 完成标准：结论中逐条确认"外部电源未与传感器电源并联"、"所有非隔离 M 端子同参考电位"；任一不满足则回到步骤 4 重做供电方案。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此能力
- 只是查某模块的订货号/针脚/端子排——那是 reference-tables.md 的纯检索，不是预算核算。
- 需要完整系统设计（分区、安全回路、操作员站）——用 `system-design-workflow`。
- 供电正常但要排 LED/诊断缓冲区故障——用 `online-troubleshooting`。

### 作者在书中警告的失败模式
- **ce03**：把外部 24V 电源与 CPU 传感器电源并联——两电源拉锯，寿命缩短/立即故障/运行不确定。
- **ce04**：非隔离 M 端子接不同参考电位——形成意外环流，损坏 PLC 与连接设备。
- **ce02**：纵向安装仍套用水平温度上限——散热裕度被悄然吃掉 10°C。

### 作者的盲点 / 时代局限
- 手册锁定 V4.2（2016）；附录 A 只覆盖当时 CPU 型号，V4.4+ 新 CPU 的预算值须查新版手册。
- 假设读者能拿到 TIA Portal 与附录 A 全表；厂商视角，不对比第三方电源方案。
- 功能安全与网络安全几乎缺席——加外部电源不能替代独立于 PLC 的急停与机电超控（见 ce10）。

### 容易混淆的邻近能力
- `installation-wiring-safety`（施工/接地规范）、`system-design-workflow`（七步设计）、`technology-motion-config`（PTO 轴数影响选型）。
