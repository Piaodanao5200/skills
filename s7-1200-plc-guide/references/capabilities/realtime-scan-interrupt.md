# 扫描周期、实时性与中断组态

## R — 原文 (Reading)

> "每个周期都包括写入输出、读取输入、执行用户程序指令以及执行后台处理。该周期称为扫描周期或扫描。" "CPU 按照 OB 对应的优先级对其进行处理，遵从高优先级在前低优先级在后的顺序执行 OB。最低优先等级为 1（对应主程序循环），最高优先等级为 26。" "如果超出组态的最大扫描周期时间，将生成错误……如果用户程序不包括时间错误中断 OB……CPU 仍保持 RUN 模式。但是，如果同一个扫描周期第二次超出最大扫描周期时间，CPU 就会进入 STOP 模式。"
>
> — Siemens AG，《S7-1200 可编程控制器系统手册》V4.2，ch5.1.2 p97；ch5.1.3 p98；ch5.1.4 p117

## I — 方法论骨架 (Interpretation)

这一能力把 PLC 的"时间行为"变成可评估、可组态的对象。基础模型是扫描周期：CPU 按"写输出→读输入→执行用户程序→通信/自诊断"循环，各次扫描耗时随负载波动；系统保证在组态的"最大循环时间"（默认 150ms，范围 1–6000ms）内完成，超时生成时间错误事件——首次超时只记诊断缓冲区仍保持 RUN，但同一周期第二次超时强制 STOP。中断会按优先级（1–26，程序循环最低）在任何阶段打断扫描，处理完从断点续执行；事件有排队上限，溢出后新事件丢失，须用时间错误 OB（OB80）响应。V4.0 起 OB"可中断/不可中断"成为组态项且默认不可中断，迁移旧项目时须复核。组态层面：循环中断每个事件一个 OB、最多 4 个，用相移（SET_CINT 设 PHASE、QRY_CINT 验证）错开同时触发，注意 SET_CINT 值掉电/STOP 后失效须重设；硬件中断须先在设备组态使能上升沿等事件，再建 OB 并绑定，否则只建 OB 不会触发；延时中断用 SRT_DINT/CAN_DINT/QRY_DINT 指令族，须用单触发脉冲启动（EN 常通会导致每扫描重启定时器）。运行期还可用 ATTACH/DETACH 动态改事件绑定（ADD=0 替换/ADD=1 追加）。临界区用 DIS_AIRT 延迟中断、EN_AIRT 恢复，必须同 OB 调用链内等量配对。系统/时钟存储器位（FirstScan、0.5–10Hz 方波）提供无块的时序信号，但属普通 M 区、可被写坏。

## A1 — 应用示例 (Application Example)

### 示例 1: 循环中断相移（worked_example，依据 f40 的 walkthrough）
- **类型与来源**: 合成演练——手册 ch9.5.2 p473–475 给出相移规则，未给完整项目。
- **问题/输入**: 5ms 与 10ms 两个循环中断 OB 同时到点，低优先级 OB 被高优先级抢占。
- **方法论的使用**: 把低优先级 OB 的相移设为大于高优先级 OB 的处理时间；用 SET_CINT 设 PHASE、QRY_CINT 验证；因 SET_CINT 不保持，掉电/STOP 后须重设。
- **结论**: 两个循环事件错开，不再同时抢占。
- **结果**: 演练与手册规则一致；实际抖动结果未说明。

### 示例 2: 时间错误 OB 排障（worked_example，依据 f10 的 walkthrough）
- **类型与来源**: 合成演练——手册 ch5.1.3.6 p102–103 给出 fault_id 判据。
- **问题/输入**: 诊断缓冲区 fault_id=16#02，csg_OBnr 指向某 OB。
- **方法论的使用**: 判为"OB 无法启动（前一次中断未完）"，定位该 OB 并优化其执行时间或中断属性。
- **结论**: 把超时排障固化为"症状→fault_id 判据→定位 OB→优化"。
- **结果**: 与手册判据一致。

### 示例 3: 延时中断单触发陷阱（worked_example，依据 f41）
- **类型与来源**: 合成演练，手册 ch9.5.4 p481–483。
- **问题/输入**: 想延后 2s 触发一次中断。
- **方法论的使用**: SRT_DINT(DTIME=2000)，用单触发脉冲启动；EN 常通会每扫描重启定时器，永不触发。
- **结论**: 到期触发一次，可用 CAN_DINT 取消、QRY_DINT 查状态。
- **结果**: 与手册"单触发"规则一致。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个能力?
1. 评估某输出从输入变化到响应的延迟有几个扫描周期。
2. 要定时执行某任务（每 10ms 定值控制），纠结用 OB1 还是循环中断 OB。
3. 两个循环 OB 总同时触发、互相抢占，想用相移错开。
4. 硬件中断建了 OB 却一直不触发，怀疑事件没使能。
5. 诊断缓冲区报时间错误/队列溢出/CPU 意外 STOP，要查实时性根因。
6. 迁移 V3 项目到 V4，担心 OB 可中断属性变化导致超时保护失效。

### 语言信号 (用户的话里出现这些就应激活)
- "扫描周期 / 响应延迟" / "scan cycle / response time / cycle time"
- "循环中断 / 相移" / "cyclic interrupt / phase shift / SET_CINT"
- "硬件中断不触发" / "hardware interrupt not firing / enable event"
- "延时中断 / 定时器每扫描重启" / "time delay interrupt / SRT_DINT / one-shot"
- "时间错误 OB / 看门狗 / 队列溢出" / "time error OB / watchdog / queue overflow"
- "OB 可中断" / "OB interruptible / V4 migration"

### 与相邻能力的区分（阶段 3 定稿）
- 与 `program-structure-decision` 的区别：那边定块角色与调用结构，本能力定执行时序/优先级/中断组态；中断 OB 是交界的事件入口（composes-with）。
- 与 `data-consistency` 的区别：那边用 DIS_AIRT/EN_AIRT 保护临界区数据，本能力提供这对指令的底层配对规则（composes-with）。
- 与 `online-troubleshooting` 的区别：那边是从 LED/诊断缓冲区入手的完整排障链，本能力专注"时间错误/队列溢出"这一类实时性根因。
- 与 `technology-motion-config` 的区别：那边把 PID 放进循环中断 OB，本能力负责循环中断本身的组态（composes-with）。

## E — 可执行步骤 (Execution)

**必需输入**: 时序需求（周期/相移/延时时长）；事件类型（硬件/循环/延时/时间错误）；OB 可中断属性；最大循环时间组态值；是否有 V3→V4 迁移。
**交付物与完成标准**: 时序分析表（响应延迟估算/监控窗口/超时行为）+ 中断组态表（OB/事件/优先级/相移/指令族/配对），含边界与陷阱核对结论。

1. **建扫描周期模型** — 完成标准：按"写输出→读输入→执行→通信"估算响应延迟（最多一个扫描周期+中断等待）；记录最大/最小循环时间组态。
2. **判定超时行为** — 完成标准：明确首次超时（记诊断仍 RUN）与同周期二次超时（STOP）；判停条件：未组态时间错误 OB 且循环接近 150ms → 必须补 OB80 后再继续。
3. **选 OB 与优先级** — 完成标准：周期性任务用循环中断 OB（非 OB1），按 1–26 优先级调度；事件映射到对应 OB。
4. **组态循环/硬件/延时中断** — 完成标准：循环中断每事件一 OB、≤4 个、相移错开（SET_CINT/QRY_CINT，含掉电重设）；硬件中断先使能事件再建 OB 绑定；延时中断用单触发脉冲启动。
5. **核对中断配对与迁移** — 完成标准：DIS_AIRT/EN_AIRT 等量同链配对、RET_VAL=0 才恢复；V4 项目 OB 可中断属性已复核（ce29）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此能力
- 要决定 OB/FC/FB 的角色与调用结构——用 `program-structure-decision`。
- 要处理多值读写撕裂——用 `data-consistency`。
- 要组态 PID/HSC/运动工艺对象——用 `technology-motion-config`。

### 作者在书中警告的失败模式
- **ce28**：超最大扫描周期却以为"默认保持 RUN 就安全"——同周期二次超时直接 STOP、队列溢出丢事件。
- **ce29**：把 V3"时间错误 OB 可中断任何 OB"套到 V4——默认不可中断导致错过超时处理窗口。
- **f40/f41**：SET_CINT 掉电失效未重设；延时中断 EN 常通导致每扫描重启定时器。
- **ce33**：DIS_AIRT/EN_AIRT 不成对、EN_AIRT 放错 OB，中断被长期禁用。

### 作者的盲点 / 时代局限
- 手册锁定 V4.2（2016）；OB 可中断属性、运动控制 OB 优先级等在新版固件可能变化。
- 手册给的默认值（150ms、4 个循环 OB、6 层中断嵌套）是硬边界，但新型号可能不同，须查新版技术规范。
- 厂商视角：只讲 S7-1200 内部调度，不涉及跨平台实时性对比；功能安全相关的安全 OB 缺席。

### 容易混淆的邻近能力
- `program-structure-decision`、`data-consistency`、`online-troubleshooting`、`technology-motion-config`。

## 相关能力（阶段 3 填充）

- composes-with: `program-structure-decision`, `data-consistency`, `technology-motion-config`
- 对照: `online-troubleshooting`（时间错误类根因由本能力提供判据）
