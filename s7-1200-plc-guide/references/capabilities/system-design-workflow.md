# PLC 系统设计七步流程

## R — 原文 (Reading)

> "此信息仅用于设计正常和预期的异常操作。出于安全考虑，不应依赖此'最佳情况'方案。"（表 7-1 给出设计步骤：分区 → 功能规范 → 安全电路 → 系统安全 → 操作员站 → 组态图 → 符号表）
>
> — Siemens AG，《S7-1200 可编程控制器系统手册》V4.2，ch7.1「设计 PLC 系统的指南」表 7-1 p199–200

## I — 方法论骨架 (Interpretation)

这一能力把"从零设计一台机器/产线的控制系统"拆成七个有先后依赖的步骤，并把"安全"作为贯穿原则而不是最后补的一步。顺序是：①按工艺把系统分区，明确每区边界与联锁关系；②为每个区写功能规范（要检测什么、输出什么、异常怎么响应）；③先设计独立于 PLC 的安全电路（急停、机电超控、冗余安全功能），这一步不能等程序写完再补；④再做系统安全设计（访问保护、故障模式下的输出行为、上电/掉电行为）；⑤设计操作员站（HMI 画面、报警文本、权限）；⑥画组态图（硬件拓扑、地址分配、通信连接）；⑦编制全项目统一的符号表与命名规范。关键判断是"安全电路前置于程序"——因为 PLC 单点故障会同时打断检测、决策、执行，任何只写在用户程序里的联锁都不可靠。手册明确警告这套指南只覆盖正常与预期异常，不能当成完整的、经认证的安全设计。

## A1 — 应用示例 (Application Example)

### 示例 1: 包装机控制系统设计（worked_example，依据 f25 的 walkthrough）
- **类型与来源**: 合成演练——手册表 7-1 给出七步顺序（p199–200），未给完整项目；以下按七步复算，非作者亲历。
- **问题/输入**: 从零设计一台包装机的控制系统，含输送、封切、检测三区，需急停与 HMI。
- **方法论的使用**: ①分区=输送/封切/检测；②每区写功能规范（传感器、执行器、异常响应）；③先做独立急停回路与门联锁，不写进 PLC 程序；④定义 STOP 时输出行为、访问保护级别；⑤HMI 画面与报警文本、操作员权限；⑥组态图列出 CPU/模块/地址/PROFINET 连接；⑦符号表统一命名。
- **结论**: 产出七类交付物，安全电路先于程序设计。
- **结果**: 演练产出与手册七步一致；实际机械运行结果未说明。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个能力?
1. 从零规划一台新设备的 PLC 控制系统，不知道先做什么后做什么。
2. 担心设计阶段漏掉安全回路或操作员站，事后返工。
3. 团队多人协作，需要统一的分区/命名/符号表规范。
4. 想检查现有设计流程是否符合系统化工程方法。

### 语言信号 (用户的话里出现这些就应激活)
- "从零设计一套 PLC 系统" / "design a PLC system from scratch"
- "系统设计流程 / 步骤" / "system design workflow / engineering steps"
- "功能规范 / 分区 / 符号表" / "functional specification / zoning / symbol table"
- "安全电路要不要先做" / "safety circuit first"

### 与相邻能力的区分（阶段 3 定稿）
- 与 `power-budget-sizing` 的区别：本能力是七步总流程，功率预算是其中硬件选型的一步（composes-with）。
- 与 `program-structure-decision` 的区别：那边细化"用户程序结构"这一步，本能力覆盖整个项目 lifecycle 的第一步到第七步。
- 与 `power-wiring-installation` 的区别：那边是物理安装与接线施工，本能力是设计阶段的纸面流程。

## E — 可执行步骤 (Execution)

**必需输入**: 工艺分区描述；功能需求清单；是否有安全联锁/HMI/通信。缺失时先问工艺范围。
**交付物与完成标准**: 七类文档——分区图、功能规范、安全电路图、系统安全策略、操作员站设计、组态图、符号表；每项标注是否满足"安全前置"。

1. **分区** — 完成标准：边界与区间的联锁关系明确成图。
2. **功能规范** — 完成标准：每区检测量/输出量/异常响应逐条列出。
3. **安全电路（前置）** — 完成标准：独立于 PLC 的急停/机电超控已成图；判停条件：若安全回路缺失，不得进入步骤 4 的程序化设计。
4. **系统安全** — 完成标准：STOP 输出行为、上电行为、访问级别均已定义。
5. **操作员站** — 完成标准：画面/报警文本/权限清单完成。
6. **组态图** — 完成标准：CPU/模块/地址/通信拓扑落图，且功率预算已用 `power-budget-sizing` 核算。
7. **符号表** — 完成标准：全项目命名统一、可被程序与 HMI 共用。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此能力
- 只做程序结构设计——用 `program-structure-decision`。
- 只算功率预算——用 `power-budget-sizing`。
- 只想查安装接线规范——用 `power-wiring-installation`。

### 作者在书中警告的失败模式
- **ce10**：把 PLC 当唯一安全屏障——安全电路必须独立于 PLC 前置设计。
- 手册自称"仅覆盖正常与预期异常"，把它当完整安全设计是误用。

### 作者的盲点 / 时代局限
- 手册锁定 V4.2（2016）；表 7-1 未覆盖现代网络安全与功能安全认证要求。
- 假设读者有 TIA Portal 与电气工程背景；纯方法论流程，急性操作员站/网络部分需查新版资料。

### 容易混淆的邻近能力
- `program-structure-decision`、`power-budget-sizing`、`power-wiring-installation`。

## 相关能力（阶段 3 填充）
