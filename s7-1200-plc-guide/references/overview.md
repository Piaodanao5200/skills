## 1. 结构（Structural）

### 类型
**实操手册 / 技术参考手册**。不是观点类书籍——没有贯穿全书的"作者论证链"，而是按功能域组织的**任务驱动型**内容：教你装、配、编、调、查、通信。

### 一句话主旨
把 S7-1200 PLC 从硬件安装、程序构建、指令使用到通信组态与在线诊断的完整操作方法，组织成可按需查阅的任务指南。

### 骨架（一级论点及关系）

15 个正文章可归为 5 大功能域，呈**层层深入的递进 + 并列**关系：

1. **基础认知域**（ch1–4 产品概述/新功能/STEP7/安装）：S7-1200 是什么、怎么装、功率怎么算。**并列**铺垫。
2. **核心原理域**（ch5 PLC概念 / ch7 编程概念）：用户程序执行机制（扫描周期、OB/FC/FB/DB）、存储寻址、数据类型、程序构建方法。这是全书**理论内核**，后续所有操作都建立其上。
3. **指令域**（ch8 基本 / ch9 扩展 / ch10 工艺）：从位逻辑到 PID/运动控制的完整指令集。**纯参考**，占比最大（p243–904，约 660 页）。
4. **通信与互连域**（ch11 通信 / ch12 Web服务器 / ch13 CP与Modbus / ch14 邮件）：PROFINET/PROFIBUS/PtP/Modbus 等协议组态。**并列**展开。
5. **运维域**（ch15 在线和诊断工具 + 附录 A 技术规范 / B 功率预算 / C 订购 / D 更换）：查故障、算功率、选型号、换设备。

**关系**：1→2 递进（认知→原理）；2→3/4 支撑（原理指导指令与通信）；5 贯穿（运维依赖前面全部）。

### 作者要解决的核心问题
让工程师能用一台 S7-1200 完成一个自动化项目：从选型安装、写程序、配通信，到上线后排障——即"如何把 PLC 用起来并稳定跑下去"。

## 2. 解释（Interpretive）

### 关键术语（作者本人的用法）

| 术语 | 作者的定义 | 与常识的差异 |
|---|---|---|
| OB（组织块） | 定义程序结构，有预定义行为/启动事件，也可自定义启动事件；分程序循环、启动、中断等 | 不只是"主函数"，而是带调度语义的事件入口 |
| FB / FC | 带参数的代码块；FB 关联背景 DB 保存实例数据，可多次调用互不干扰 | FB 的"实例"概念是核心，与普通函数不同 |
| DB（数据块） | 存储程序块可用数据的区域 | — |
| 扫描周期 | 每个周期写入输出→读取输入→执行用户程序（含中断打断） | 实时性的基本单位，决定响应延迟 |
| 过程映像 | CPU 在周期开始读输入到映像区、周期末写输出 | 区别于直接 I/O 访问（立即外设访问） |
| 一致性数据 | 在同一扫描周期内保持逻辑一致的数据交换 | 涉及数据传输的原子性问题 |
| 中断 OB | 与标准或错误事件关联，事件触发时执行（有嵌套深度 6 的限制） | 事件驱动，打断循环 |

### 核心命题（用自己的话）

1. 用户程序的结构由 OB 决定：启动 OB 跑一次，程序循环 OB 反复跑，中断 OB 由事件触发。
2. FB 通过背景 DB 实现可重入——同一 FB 配不同 DB 多次调用，数据互不干扰。
3. 循环扫描是确定性实时行为，但会被更高优先级的中断 OB 打断，且中断间有排队/优先级。
4. PLC 程序不是"写完就完"，必须配合在线诊断、跟踪、断点等工具调试验证。
5. 通信是协议族选择问题：PROFINET/PROFIBUS/PtP/Modbus 各有适用域与组态流程。
6. 功率预算是硬性设计约束，安装前必须算，否则供电不足。
7. 数据一致性在跨周期/跨通信场景下必须显式处理，否则会出现读写撕裂。

### 论证链
非论证型文档。证据链是"步骤 + 参数表 + 图示 + 注意/警告提示"，用规范性陈述（"必须""建议""注意"）建立权威。

## 3. 批判（Critical）★ 下游 Boundary 来源

### 时代局限
- **版本锁定 V4.2（2016）**：TIA Portal 与固件已迭代多版（V4.4+ 等），部分新功能/新 CPU 型号未覆盖，命令路径可能已变化。
- 涉及的"早期 PtP/USS/Modbus 通信"（ch13.6–13.9）明确是旧模块遗留，新项目不应照搬。

### 立场盲点
- **厂商视角**：只讲西门子方案，不涉及与三菱/AB 的对比或迁移；型号推荐天然导向西门子产品。
- **假设读者有 TIA Portal 环境与硬件**：没有环境的读者无法验证多数步骤。
- **安全（ cybersecurity）与功能安全（Failsafe）着墨极少**：现代工业的核心议题在这本 2016 手册里几乎缺席。

### 未被证明的假设
- 假设读者具备基本电工与编程素养（梯形图、电气接线）。
- 假设"按手册步骤操作即可"——实际工程中的接地、抗干扰、网络拓扑规划等经验性知识不在书中。

### 最强反对意见
"手册是查阅工具，不是方法论——把它蒸成 skill 有过度抽象的风险。" 这直接决定了我们的策略：**优先蒸馏决策型/流程型/计算型内容（排障、选型、功率预算、程序结构决策），纯指令语法与参数表保留为检索参考，不硬蒸成 skill。**

> 以上批判直接成为下游各 skill 的 Boundary（B）字段来源。
