## 簇一 · 程序结构与调度核心

本簇是全书理论内核。理解"OB 是事件入口而非函数""FB 靠背景 DB 实现实例"是程序结构决策与实时性评估的前提。

### g01 OB（组织块 / Organization Block）
- **作者定义**：「组织块 (OB) 定义程序的结构……充当操作系统和用户程序之间的接口。OB 是由事件驱动的。」（p89、p204）
- **关键区分**：≠ 主函数 / main()，也 ≠ 可互相调用的子程序——OB 由事件触发、由 OS 调度，OB 之间及被 FC/FB 调用均不允许。它 = 带编号、启动事件与优先级（1–26）的事件入口；分程序循环、启动、中断/错误 OB。
- **为何重要**：程序结构决策（T02）须先讲清 OB 是"事件入口"，否则会把中断 OB 误当可调用子程序。

### g02 中断 OB 与事件优先级/排队
- **作者定义**：「CPU 按照 OB 对应的优先级……高优先级在前。最低 1（主程序循环），最高 26。」「达到未决事件限值后，下一个事件将丢失。」（p98、p114–116）
- **关键区分**：≠ 异常捕获 try-catch（中断是硬件/系统事件驱动、按固定优先级调度）；≠ 无限嵌套（从中断 OB 起最多 6 层，从循环/启动 OB 起 16 层）。事件会排队、有上限，溢出用时间错误 OB（OB80）响应。V4.0 起 OB 可组态为可中断/不可中断。
- **为何重要**：实时性与排障（T03/T07）须区分"中断打断→断点续执行"与顺序执行；队列溢出须落到 OB80 而非普通报警。

### g03 FC（功能 / Function）
- **作者定义**：「FC 不具有相关的背景数据块 (DB)……采用局部数据堆栈。不保存临时数据。要长期存储，可将输出值赋给 M 或全局 DB。」（p205）
- **关键区分**：≠ 通用编程的"函数"——FC 无静态存储、临时数据块结束即丢失、不跨扫描保留；≠ FB——无背景 DB、无实例概念。它是无状态的可复用运算块，靠参数传入传出。
- **为何重要**：T02 中"何时用 FC、何时用 FB"的分水岭就是"是否需跨扫描保存状态"；按常识把 FC 当普通函数会写出丢数据的程序。

### g04 FB（功能块 / Function Block）与实例
- **作者定义**：「FB 还使用相关联的数据块（称为背景数据块）来保存该 FB 调用实例的数据值……调用带有不同背景数据块的同一 FB 不会对其它任何背景数据块的数据值产生影响。」（p89、p206）
- **关键区分**：FB 自带背景 DB 保存参数与静态数据，跨扫描保留；同一 FB 配不同背景 DB 可控制多台设备且互不干扰（可重入）。"实例 = FB 的一次调用 + 专属背景 DB"，是 S7 面向对象式复用的核心。
- **为何重要**：T02"一个 FB 控制多台泵/阀"完全依赖实例概念；每次调用必须指定唯一背景 DB，否则多台设备数据串扰。

### g05 背景 DB / 实例数据块（Instance DB）
- **作者定义**：「背景 DB 存储特定 FB 的数据。其结构反映 FB 的参数（Input/Output/InOut）和静态数据。」（p207）
- **关键区分**：≠ 私有数据——手册明确"任何代码块都可访问背景 DB 中的数据"，并非访问隔离；≠ 全局 DB——全局 DB 存共享数据，背景 DB 结构由 FB 接口决定、专属一次调用。
- **为何重要**：T02 与诊断须提醒：共享背景 DB 时不要误以为数据受保护；FB 间串扰根因常是复用了同一背景 DB。

### g06 DB（数据块 / Data Block）
- **作者定义**：「数据块 (DB) 存储程序块可以使用的数据。全局 DB……任何 OB、FB 或 FC 都可访问；背景 DB 存储特定 FB 的数据。」（p89、p207–208）
- **关键区分**：≠ 数据库/数据表——DB 是 CPU 中的一块存储区，掉电后当前值不删除（配保持性后跨掉电）。分全局 DB（所有块可访问）与背景 DB（绑定 FB 实例），可组态只读、标准/优化访问。
- **为何重要**：数据类型与寻址（T02）、数据一致性（T04）、Modbus/PROFINET 数据交换都围绕 DB 展开；须区分"优化访问 DB 无固定地址"。

### g07 扫描周期（Scan Cycle / 扫描）
- **作者定义**：「每个周期都包括写入输出、读取输入、执行用户程序指令以及执行后台处理。该周期称为扫描周期或扫描。」（p89、p97）
- **关键区分**：≠ 简单"循环执行一次程序"——它是确定性实时单位，且会被更高优先级事件在任何阶段打断；≠ 固定频率——各次扫描耗时随负载变化，除非组态最小扫描周期。系统保证在"最大循环时间"内完成，超时生成时间错误事件。
- **为何重要**：T03 实时性评估的全部基础；响应延迟以扫描周期计，超过扫描速率的事件须用 HSC 而非普通指令。

## 簇二 · 存储、寻址与数据一致性

本簇回答"变量放哪、地址怎么写、多个值怎么保证同时正确"。易错点集中在过程映像 vs 立即访问、优化 DB 无固定地址、多值撕裂。

### g08 过程映像（Process Image）
- **作者定义**：「每个扫描周期开始……将输入当前值写入过程映像；周期末将输出映像写入物理输出。」「对 I/Q 存储区的引用会访问过程映像。」（p97、p127）
- **关键区分**：≠ 直接读/写物理 I/O——普通 I/Q 访问的是周期初/末刷新的快照，非实时引脚；要立即访问物理点须加 `:P`。输入映像周期初刷新、输出映像周期末写回，带来最多一个扫描周期延迟与一致性边界。
- **为何重要**：T03/T04 须区分过程映像与立即访问：响应延迟、数据撕裂、"通过指令访问物理输出会同时更新映像"的副作用都源于此。

### g09 `:P` 立即外设访问（立即 I/O）
- **作者定义**：「要立即访问物理输入或输出，请在引用后添加 ':P'（如 I0.3:P、Q1.7:P）。」「I_:P 访问不更新输入映像；Q_:P 既影响物理输出，也影响输出映像。」（p127、p130）
- **关键区分**：≠ 换地址写法——它绕过过程映像直接读物理点；I_:P 只读且不更新映像，Q_:P 只写且同时改映像。强制（I）只能强制外设输入 `:P`，不能强制过程映像输入。
- **为何重要**：在线诊断与强制（T07）"强制 I 点必须写 I_:P"、精确定时控制都要用 `:P`；误用普通 I/Q 会读到陈旧快照、调试结论错误。

### g10 过程映像分区（PIP, Process Image Partition）
- **作者定义**：「可将输入和输出分配给 PIP0–PIP4 或自动更新，或不使用过程映像分区。」「中断事件时，CPU 读取输入、执行 OB，再用关联的 PIP 写输出。」（p97、p192）
- **关键区分**：≠ 自动更新的过程映像——PIP 是可由特定 OB 单独更新的子分区；分配后该 I/O 不再随主扫描自动刷新。注意关键陷阱：分配了 PIP 但未绑定 OB 等价"无 PIP"，该 I/O 永不刷新。
- **为何重要**：T03/T06 实时性与运动组态：高频 I/O、硬限位应分配到 OB 伺服 PIP 才能与工艺对象同步，否则滞后一个扫描周期。

### g11 一致性数据（Consistent Data）
- **作者定义**：「用 DPRD_DAT/DPWR_DAT 一致性地读取/传送一个或多个字节……PROFINET 最多支持 1024 字节一致性数据。使用这些指令时，必须从过程映像自动更新中删除该一致性数据。」（p454–455）
- **关键区分**：≠"数值正确"——"一致性"专指数据传输的原子性：多字节一次整体刷新、不被扫描/通信中途撕裂。≠ 默认行为——普通过程映像刷新不保证跨模块/跨周期一致。S7-1200 一致性外围 I/O 读写仅支持 1、2、4 字节。
- **为何重要**：T04 数据一致性方案必须显式处理：多字节/跨通信数据不用一致性指令并脱离自动更新，会出现半新半旧的读写撕裂。

### g12 三级存储：装载 / 工作 / 保持性存储器
- **作者定义**：装载存储器非易失存程序/数据/组态（在卡或 CPU 中）；工作存储器易失、断电丢失、恢复供电时由 CPU 恢复；保持性存储器非易失存限量工作值。（p119–120）
- **关键区分**：≠ 笼统"内存/闪存"——三者分工：装载≈硬盘、工作≈RAM、保持性≈掉电保留少量运行值。起始值始终在装载存储器，当前值在工作存储器；READ_DBL/WRIT_DBL 在两者间搬运。
- **为何重要**：T04 数据一致性、T10 维护（存储卡/掉电恢复）都依赖三级存储模型；工作存储器容量限制程序大小，保持性决定掉电后值是否保留。

### g13 保持性（Retain / 保持性数据）
- **作者定义**：「暖启动不包括存储器复位……初始化所有非保持性数据，保留所有保持性用户数据值。」「标记保持性可避免电源故障后数据丢失。」（p93–94、p120）
- **关键区分**：≠"掉电后所有数据都保留"——只有显式标记保持的 M 区/DB/FB 变量才跨掉电；非保持区暖启动时清零或复位为装载存储器初值。保持性位从 MB0 起连续。
- **为何重要**：T10 恢复/掉电处理与 T04 状态保存须显式规划保持范围；累计量、配方未设保持会在上电后丢失，是常见现场故障根因。

### g14 暖启动（Warm Start）与存储器复位（MRES）
- **作者定义**：「CPU 通过暖启动进入 RUN，暖启动不包括存储器复位。」「存储器复位将清除所有工作/保持/非保持存储区、把装载存储器复制到工作存储器……不清除诊断缓冲区和永久 IP。」（p93–94）
- **关键区分**：≠"重启=恢复出厂"——暖启动保留保持性数据、只初始化非保持数据；MRES 才彻底清空并重载项目。MRES 不清除诊断缓冲区和永久 IP。"暖启动-断电前的模式"按掉电前状态决定回 RUN 还是 STOP。
- **为何重要**：T10 维护排障须区分二者：误执行 MRES 会丢失保持性数据与组态，但诊断缓冲区仍在可用于追溯故障。

### g21 Variant（参数化数据类型）
- **作者定义**：「INPUTS IN_OUT Variant 读取数据所在的目标区域……可用系统数据类型、UDT、STRUCT（仅未优化 DB）等。」（p431、p632）
- **关键区分**：≠ 通用语言的"动态类型"——Variant 是 S7 的指针式参数类型，允许指令接受多种类型，但实际可用类型受指令限定（STRUCT 仅允许未优化 DB）。它只描述"可被传入的实参形态"，不决定物理存储。
- **为何重要**：T04/T06 使用扩展/工艺指令时，Variant 的类型限制（优化 DB 不可用 STRUCT）是常见编译/运行错误来源，须显式提示。

### g22 优化块访问 / 标准块访问（Optimized Block Access）
- **作者定义**：「可优化访问的数据块无固定定义结构……元素只有符号名、无固定地址……默认新 DB 选中优化访问。」「标准 DB 与 STEP 7 Classic 及 S7-300/400 兼容。」（p208）
- **关键区分**：≠ 单纯"存储效率选项"——优化 DB 元素无固定绝对地址、只能符号寻址；这决定它能否用于需绝对/直接寻址的场合（Modbus DATA_PTR、Variant 的 STRUCT 实参、CTRL_HSC_EXT 起始值）。默认优化，需绝对寻址时须显式改标准访问。
- **为何重要**：T04/T05/T06 中 Modbus 保持寄存器、DPRD_DAT、HSC 明确要求标准访问 DB；沿用默认优化 DB 会报"无绝对地址"类错误，是高频坑点。

## 簇三 · 实时性、负载与诊断

本簇是排障取证与实时性评估的数据来源。诊断缓冲区是"第一现场"，循环时间监视决定超时行为。

### g15 循环时间监视（最大/最小扫描周期时间）
- **作者定义**：「CPU 提供两种监视循环时间的方法：最大扫描周期时间、最小扫描周期时间。」「最大扫描周期始终启用，默认 150 ms；最小扫描周期可选、默认禁用。」（p117–118）
- **关键区分**：≠"扫描越快越好/无上限"——CPU 强制监视最大周期（1–6000 ms，默认 150 ms），超时触发时间错误事件。最小周期仅让 CPU 在程序完成后延时，用于消除扫描时长波动。RE_TRIGR 可复位监视定时器，但同一周期第二次超时必进 STOP。
- **为何重要**：T03 实时性评估须给出监控窗口与超时行为；排障时超时条目须结合最大周期组态解读（见 ce28）。

### g16 通信负载（Communication Load）
- **作者定义**：「通信负载：可组态一个百分比时间，专门用于通信任务。」「STEP 7 计算通信负载，然后计算产生的更新时间。」（p118、p1060）
- **关键区分**：≠"通信不占 CPU 时间"——通信处理在扫描周期中定期执行并占专门百分比时间，会拉长扫描周期、挤占用户程序窗口。它是可组态资源，也是 PROFINET 更新时间（发送时钟）计算前提。
- **为何重要**：T03/T05 通信与实时性联动：通信负载过高增加扫描抖动；PROFINET 更新时间由通信负载反算，须纳入选型与诊断。

### g17 诊断缓冲区（Diagnostic Buffer）
- **作者定义**：「每个条目对应一个诊断事件，含日期/时间、类别、描述，最新在最上。最多 50 个最近事件，满后新事件替换最早事件。掉电时保存。仅永久存储 10 个最新事件。」（p123、p1497）
- **关键区分**：≠ 完整运行日志——容量有限（最多 50 条、仅 10 条永久）的环形缓冲，旧事件会被覆盖；≠ 只记故障——也记录每次状态切换与系统诊断事件。是排障"第一现场"，须在线访问，MRES 不清除它。
- **为何重要**：T07 排障核心数据源：定位故障先读诊断缓冲区，且要理解"50 条/10 条永久"覆盖特性，避免误判事件未发生；高频重复安全事件会刷屏冲掉关键线索（ce43）。

## 簇四 · 通信与互连

本簇是 PROFINET 角色体系的关键区分。选错角色会将智能设备当普通 IO 设备，丢失预处理与知识保护价值。

### g18 PROFINET IO 角色：IO 控制器 / IO 设备 / 智能设备（I-Device）
- **作者定义**：「PROFINET 网络中的设备在分配名称后才可与 CPU 连接。」「智能设备功能简化与 IO 控制器的数据交换……作为 IO 设备链接到上位控制器，预处理由 CPU 用户程序完成。」（p1041、p1044–1045）
- **关键区分**：≠ 普通主/从——IO 控制器/IO 设备是 PROFINET 确定角色；"智能设备"是既具备自身用户程序预处理、又作为 IO 设备挂到上位控制器的双重角色 CPU。设备须先分配名称才能连接；智能设备通过 GSD 文件（非 STEP7 项目）向上位站暴露接口，保护专有知识。
- **为何重要**：T05 通信选型须在"普通 IO 设备/智能设备/共享设备"间正确选择；把智能设备当普通 IO 设备会丢失其预处理与知识保护价值。

### g19 共享设备（Shared Device）
- **作者定义**：「共享设备功能允许 IO 设备的模块或子模块在不同 IO 控制器中划分……每个子模块以独占方式分配给一个 IO 控制器。」（p1053–1055）
- **关键区分**：≠"多控制器同时读写同一模块"——共享的是物理设备，但每个子模块被"独占"分配给一个控制器，是拆分控制权而非共享数据。≠ 自动生效——须在多个项目中一致组态访问权，否则访问参数错误只在这行时以组态错误暴露。
- **为何重要**：T05 多控制器分布式系统须明确：共享设备解决"多个邻近 I/O 模块供不同控制器"问题，但访问权/发送时钟/IP 必须跨项目一致，否则隐性故障难排查。

## 簇五 · 工艺对象与在线工具

本簇是工艺组态（T06）与排障调试（T07/T08）的入口概念。HSC 突破扫描速率限制，PTO 用于开环轴，Trace 捕捉间歇异常。

### g20 工艺对象（Technology Object, TO）
- **作者定义**：「展开'工艺对象'节点→添加新对象→选'轴'图标→打开组态编辑器。」「STEP 7 为'轴'工艺对象提供组态、调试和诊断工具……组态数据保存在工艺对象 DB 中。」（p751、p754）
- **关键区分**：≠ 普通 OOP 实例——TO 是预置的、带专用组态/调试/诊断 UI 的功能封装（轴、PID 等），参数保存在专属 TO-DB，由系统 OB 驱动。≠ 可直接 new 的软件类——必须通过项目树添加并下载，重命名后须在 STOP 重新下载保证一致性。
- **为何重要**：T06 工艺组态以 TO 为入口轴心；运动控制应用周期（轴数×2 ms）、MC-Servo OB、OB 伺服 PIP 都挂在 TO 体系下。

### g23 高速计数器（HSC, High-Speed Counter）
- **作者定义**：「基本计数器指令限于低于扫描速率的计数事件。HSC 提供高于 PLC 扫描速率的计数脉冲……下载硬件组态后，HSC 无需任何调用指令即可计数。」（p631–632）
- **关键区分**：≠ 普通计数器指令——普通计数器受扫描速率限制会漏计高频脉冲；HSC 由硬件实现、组态后无需调用即可运行，值通过过程映像或 CTRL_HSC_EXT 的 DB 访问。运动控制中 HSC 与 PTO 有固定配对。
- **为何重要**：T06 工艺组态须按"事件频率 vs 扫描速率"选 HSC 还是普通计数；否则编码器/高速脉冲场景严重漏计。

### g24 PTO（脉冲串输出 / Pulse Train Output）
- **作者定义**：「PTO（脉冲 A 和方向 B）：一个输出控制脉冲，另一输出控制方向……开环运动控制用 PTO，CPU 需板载或 SB 高速数字量 I/O，限制可轴数。」（p749、p753）
- **关键区分**：≠ 普通数字量输出——PTO 是板载/SB 高速脉冲硬件功能，用于开环运动控制，占用高速输出资源、数量受 CPU 型号限制。≠ 闭环接口——闭环用模拟量 I/O 或 PROFIdrive，不需 PTO。
- **为何重要**：T06 运动控制选型须区分开环（PTO）/闭环（模拟量或 PROFIdrive）：轴数、可用输出资源、是否需编码器都由此决定。

### g25 在线工具：监视 / 修改 / 强制 / 轨迹（Trace）
- **作者定义**：「可显示/监视变量当前值（不改变程序顺序）；可修改在线 CPU 变量值；可将外围设备输出强制为特定值。」「强制值存储在 CPU 中，不在监视表格中。无法强制 I，只能强制外围输入。」（p239–240、p1500、p1522）
- **关键区分**：≠"调试=改程序"——监视只读、修改仅临时改值、强制把值锁存在 CPU 中覆盖实际 I/O（只能强制 :P，危险极高）、Trace 按触发条件高速记录变量（需存储卡）。强制与修改不同：强制不受程序刷新覆盖、须用强制表格解除。
- **为何重要**：T07/T08 排障调试须严格区分三者：误用强制会导致输出长期锁定在危险状态（MAINT LED 指示），是现场安全事故常见来源；强制值还随项目/存储卡传播（ce24）。
